# Session 截斷提示準確性與歷史預覽穩定化

共同前綴：`session-truncation-v1`。狀態：需求、設計及實作已完成；本機驗收通過，父 agent 已核對。本文記錄離線及 fixture 驗收，不追蹤目前部署狀態；後續部署另行授權。見[設計](session-truncation-v1-design.md)與[驗收](session-truncation-v1-verification.md)。

## 目標及完整性評估

使用者要求查明短訊息或較舊訊息出現「內容已截斷；可按需讀取較完整預覽」的原因，並完成修正。授權唯讀檢查指定本機 session（完整識別與 hash 僅在 Git 忽略的本機證據保存）。不需要完整訊息匯出、不需無限長顯示。現有安全與有界讀取要求繼續有效。

已具備問題情境、來源、限制與可驗收結果，足夠開始設計。採用下列範圍，不把部署、服務重啟或真模型操作視為隱含授權。

## 使用情境與需求

- **R1 短訊息及隱私省略**：使用者讀取短 assistant 訊息。若只有 thinking、system、signature、stderr 等安全省略，且其他資料未因預算裁切，不得顯示內容截斷。仍不得將敏感資料送到瀏覽器。
- **R2 新訊息加入**：同一筆舊訊息留在當前分支。固定單筆 preview 設定時，不得因頁內有較新的大訊息，就降低舊訊息的單筆解析預算。放不進整頁時，必須可由既有游標讀下一頁，不得縮成空白或遺失。
- **R3 真正有界預覽**：單筆超過安全上限仍可裁切，且須標示。提示必須區分「歷史項目部分資料未載入」與可見文字真的被裁切；不得把項目層級旗標說成每段文字均不完整。工具參數或附加資料也可能使項目成為預覽。
- **R4 可操作且不過度承諾**：保留載入舊歷史及重載最新頁。文案說明較大預覽仍有上限，且重載只處理最新頁，不保證展開較舊項目。避免頁面同時列出全域與全部 entry 的重複警告。
- **R5 安全及相容性**：維持原生 JSONL 唯一來源、唯讀、分支順序、簽署游標、來源 identity 檢查、工作時間與讀取量限制。單次 response 不超過 1 MiB；parser retained bytes 不超過 256 KiB。不新增持久歷史索引或對話副本。不修改 session、資料庫、lock、owner 或 runtime。

## 驗收

1. 私密省略加短公開文字：文字完整，無誤報；私密內容不出現在投影/API/DOM。
2. 真正超長公開文字：明示預覽，不突破既有上限；私密標記出現在欄位尾端時仍安全。
3. 合成 append：先驗證舊版本可觸發；修正後沿游標找回同一 entry，文字與旗標不因頁內預算改變。翻頁無遺漏、重複或迴圈。
4. 原 session 唯讀重驗：記錄來源前後 hash、每頁上限、已觸發案例的前後結果，不輸出原文。若檔案變更，不把不同快照直接當比較基準。
5. UI 測試涵蓋一般短訊息無警告、真預覽有項目範圍提示、最新頁重載限制文案與翻頁操作。既有 unit、型別、lint、build 與 browser 回歸由 worker 執行。

## 非目標

不移除所有截斷、不提高到無界預算、不新增逐 entry 完整內容 API、不更換 Pi 格式、不部署、不用真模型重跑原對話。若出現損壞記錄、失效游標或工作預算耗盡，保留現有安全錯誤與續讀／重新載入方式。
