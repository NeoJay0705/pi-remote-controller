# Session 閱讀空間優化 v2 — 需求

狀態：需求已確認，程式實作與隔離驗收已完成；未操作正式服務。使用者接受第 5 節的集中收合配置及「檔案更新」時間語意；輸入區依第 5.C 節實作。設計見 `session-layout-v2-design.md`，驗收範圍與限制見 `session-layout-v2-verification.md`。

## 1. 目標

減少 Session 對話上方及輸入區的常駐堆疊，增加訊息與草稿的可用空間。簡化清單資訊，讓使用者能按最近更新時間尋找 Session。

目標名稱：**Session 閱讀空間優化 v2**。

文件共用前綴：`session-layout-v2`。設計達到可實作程度後，另歸檔 `session-layout-v2-design.md`。

## 2. 使用情境

1. 使用者在桌面或窄螢幕閱讀長對話。頁首、狀態、Profile 及 Session 資訊不得持續以多個常駐列壓縮對話。
2. Session 名稱或 ID 很長時，頁首不應因完整 ID 換行而佔用多列。
3. 使用者在同一 Project 的受管清單選取 Session。清單保留可辨識資訊，不顯示 App ID 和 Profile。
4. 使用者加入既有 Pi session。候選清單顯示時間，並與受管清單採相同的新到舊排序原則。
5. Pi 尚未啟動時，提示文字與相鄰內容使用一致的水平縮排。
6. 使用者輸入長 prompt。Compact 不應為此獨佔一整列；調整位置不得改變操作種類、限制或快捷鍵。
7. 連線失敗、runtime blocked 或操作結果不確定時，使用者仍能看見必要提示。節省空間不等於移除安全行為。

## 3. 已確認需求

- R1：減少對話上方的常駐區塊及頁首換行。具體配置須先向使用者說明建議。
- R2：移除「最近操作收據」資訊的畫面區塊。
- R3：受管 Session 清單不顯示 App ID 和 Profile。此要求不等於刪除新建／加入所需的 Profile 選擇器，也不等於刪除既有 Session 的 Profile 切換功能。
- R4：Session 有有效更新時間時，受管清單按新到舊排序。
- R5：加入既有 Session 的候選清單也按新到舊排序，並標注時間。
- R6：修正「Pi 尚未啟動；首次送出 prompt 時才會開始操作。」的水平縮排，使其與相鄰區塊一致。
- R7：評估將 Compact 移至 Prompt 上方，以增加文字區可用空間。不能只搬移按鈕卻使常駐操作列增加。

## 4. 實作前的原始碼核對結果

以下為設計前的靜態閱讀基準，不描述實作後現況，也不代表當時已執行測試：

- `src/web/main.tsx` 的頁首目前分別顯示名稱、Pi session ID、App ID；旁邊為連線狀態。
- 頁首下另有 Runtime／Provider／Model／Thinking、Session Profile 及 Session 資訊三個區塊。
- Compact 位於獨立 actions 列；手機版草稿輸入與送出按鈕會另行換列。
- released 提示為直接放在主內容下的段落，未套用相鄰 controls 的水平 padding。
- `src/web/api.ts` 的 Session 與 NativeCandidate 型別均沒有更新時間欄位；目前相關清單 API 也未回傳該欄位。
- Ledger 的 Session 記錄沒有更新時間欄位。不可把操作建立時間、ID、檔名或加入時間直接宣稱為 Session 最後更新時間。
- 收據保存及查詢與 UNKNOWN／DISPATCHED 的處理共用。移除畫面不應直接連同安全機制刪除。

## 5. 已接受的配置與時間語意

以下建議已由使用者確認，為本輪設計依據：

### A. 精簡頁首與資訊入口

- 常駐單列顯示手機選單、Session 名稱、Runtime、連線狀態及一個「Session 設定與資訊」入口。
- 名稱超長時以省略號顯示，不推擠連線狀態。完整名稱仍可在資訊區取得，不只依賴滑鼠 hover。
- 完整 Pi session ID、App ID、Provider、Model、Thinking、已保存 Profile、Profile 切換及既有診斷／複製功能移入同一個預設收合的資訊區。
- 不再為狀態、Profile、資訊入口各留一整列。展開區需有高度限制與內部捲動，不能將對話及送出區推到畫面外。
- Runtime、連線、blocked 警告與錯誤仍可直接辨識，不藏在資訊區。切換 Session 後資訊區回到收合狀態。
- 取捨：閱讀空間增加；查看模型、Profile 或完整 ID 多一次展開操作。

### B. 清單時間語意

- 建議採原生 Session JSONL 檔案的最後修改時間，標示為「檔案更新」。它不等於最後一則訊息時間，也不等於模型工作完成時間。
- 建議兩個清單都顯示本地絕對日期與時間，並可辨識時區。避免只顯示會隨時間失準的「幾分鐘前」。
- 有效時間按新到舊排序；缺失或無效時間放最後，顯示「時間未知」。相同時間使用固定識別值作次排序，避免清單跳動。
- 時間讀取失敗不得使整份清單失敗，也不得偽造為現在時間。候選檔案原有的安全錯誤仍須保留，不能因只有時間未知就允許加入不安全檔案。
- 延用既有清單載入與重新整理時機，不新增背景輪詢；不承諾每個串流事件都即時重排側欄。
- 取捨：可用一致且不需掃描完整歷史的時間依據；但檔案複製、還原或外部工具修改也可能改變時間。

### C. 輸入區

- 桌面採左側草稿、右側操作欄，Compact 放在 Prompt 上方。移除原本 Compact 獨佔的橫列。
- 手機維持草稿全寬，Compact 與文字送出按鈕放在緊湊操作區。避免為了對齊桌面而犧牲輸入寬度。
- 保留 running 時的停止按鈕及其安全文案；停止操作不得藏進設定區。
- 提示文字放進與輸入區共用水平縮排的區域。
- 不改 Prompt／Steering／Follow-up 的 eligibility、IME guard 或 Ctrl/Cmd+Enter 行為。

## 6. 邊界與錯誤處理

- 移除收據清單 UI，不移除 operation ID、去重、既有收據保存／查詢及 UNKNOWN 不自動重送規則。
- 若移除 UI 後既有錯誤不足以說明「結果不確定、不要重送」，最終設計須補足所屬 Session 的必要提示；不另建完整收據面板。
- 保留 session 錯誤隔離、generation guard、登入逾期處理、Profile 安全限制、歷史分頁及聊天跟隨捲動。
- 任何時間欄位擴充都須延用既有路徑、檔案身分及權限檢查；不得改成任意路徑 stat 或放寬安全條件。
- 本輪不改 runtime 所有權、模型、Session 格式或資料庫 schema，除非後續設計發現必要性且重新說明。
- 不操作正式 Session、不重啟服務、不執行真模型驗收。程式完成與正式部署分開回報。

## 7. 設計核定後的驗收方向

- 桌面與手機的長名稱／長 ID 不造成頁首多列或整頁水平溢出；完整值可透過鍵盤與觸控取得。
- 預設只剩精簡頁首，不再有三個獨立常駐資訊列；展開後仍可閱讀訊息及到達送出區。
- 最近操作收據區塊不存在；操作安全行為不退化。
- 受管清單不呈現 App ID／Profile，但新建、加入與切換 Profile 仍可使用。
- 兩份清單覆蓋新舊時間、同時間、缺失／無效時間、時間讀取失敗與不同 Project；加入成功後仍排除已管理項目。
- released 提示與輸入區水平對齊；Compact 移位後仍只送 compact，且原禁用條件不變。
- 既有停止、草稿、錯誤隔離、歷史捲動與 UNKNOWN 不重送須回歸。
- 實作階段由 implementation-worker 執行隔離測試。具體命令與可量測的版面條件於設計檔固定後再派工。

## 8. 執行順序

父 agent 歸檔設計後，實作與測試委派給 implementation-worker，並由父 agent 核對成果。程式與隔離驗收完成後再回報；不操作正式服務。本文件不宣稱本輪網頁優化已完成。
