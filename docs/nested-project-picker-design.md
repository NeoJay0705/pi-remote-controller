# nested-project-picker — Design

Assumptions: single owner, low traffic, no concurrency concerns beyond atomic file write. Root-relative paths use `/` and are never absolute.

## Server

New `src/server/project-picker.ts`:
- `resolveUnderRoot(root, rel)`: `rel` is a `/`-separated path relative to root (`""` = root, allowed only where stated). Reject (`invalid_directory_path`) when: not a string, any segment empty/`.`/`..`/starting `.`/containing `\` or NUL. Walk from root with `lstat` per segment (must be a real directory, not a symlink) and require `realpath(result) === join(root, rel)`. Returns the absolute path. Every filesystem failure (ENOENT, ENOTDIR, EACCES, ...) is normalised to `invalid_directory_path`, never `internal_error`.
- `listDirectories(config, rel)` → `{ path, entries: string[] }`: names of real sub-directories that the picker can enter (not hidden, no `\`), sorted (`localeCompare`); more than 10000 entries → `project_discovery_too_large`.
- `createDirectory(config, parentRel, name)`: validate name (N3), resolve parent, check that `piSessionDirectory(sessionRoot, newCwd)` basename is ≤255 UTF-8 bytes (else `invalid_directory_path`) BEFORE `mkdir`; non-recursive `mkdir`; `EEXIST` → `directory_exists` (409), `ENOENT`/`ENOTDIR` → `invalid_directory_path`, other errors → `directory_create_failed` (400). Returns `{ path }` (root-relative).
- `selectProject(config, rel)`: `rel` must be non-empty and resolve; apply the same 255-byte session-directory-name check. Build the candidate with the shared helper (below) BEFORE persisting, so an id/cwd collision or a static-project match is detected first (`project_discovery_collision` → nothing persisted). If a static project has the same cwd, return that project (id, name, custom `sessionDir` preserved). Otherwise add `rel` to the persisted list (skip if already present), run `refreshDiscoveredProjects(config)`, and return `{ id, name }` of the project whose cwd matches. Selecting a first-level directory returns its existing id.
- Read–modify–write of the persisted file is serialised with a module-level promise queue (two browser tabs).
- Without `config.projectDiscovery` every function throws `project_discovery_unavailable`.
- Persistence: `<dataDir>/picked-projects.json` = `{"version":1,"paths":[rel,...]}`, root-relative. Read: missing file → empty; malformed → treated as empty. Write: `mkdir -p dataDir` (0700), write tmp file (0600) then `rename`.

`src/server/project-discovery.ts` `refreshDiscoveredProjects`: after the first-level scan, load the persisted paths; for each, `resolveUnderRoot`, skipping silently on failure (e.g. directory deleted; entry stays in the file). Build the Project exactly like first-level ones (extract a shared helper `projectForCwd(config, cwd)` that also applies the existing static-project-by-cwd preservation and collision check: `id = repo-<sha256(cwd)[0:24]>`, `name` = root-relative path for picked ones, `sessionDir = piSessionDirectory(sessionRoot, cwd)`, same collision check) and merge into `found`, deduplicated by id. Because `loadConfig` already calls `refreshDiscoveredProjects`, picked projects are present in `config.projects` before runtime/CLI session lookups after a restart (`runtime.ts` and `cli/main.ts` resolve projects from `config.projects`).

`src/server/errors.ts`: add `invalid_directory_path` and `directory_create_failed` (400 by default) and `directory_exists` (409) to `KNOWN_ERRORS` / the 409 list.

`src/server/app.ts` (all under the existing `/api/` auth, Origin and JSON hooks; body schemas use the existing `object()` strict check):
- `GET /api/v1/directories?path=<rel>` → 200 `{ path, entries }` (`path` default `""`, must be a single string).
- `POST /api/v1/directories` body `{ parent: string, name: string }` → 201 `{ path }`.
- `POST /api/v1/projects` body `{ path: string }` → 200 `{ id, name }` (idempotent).
Errors go through the existing `error()` helper.

## Web
- `src/web/api.ts`: `directories(path)`, `createDirectory(parent, name)`, `selectProject(path)`.
- New `src/web/DirectoryPicker.tsx`, rendered in the sidebar under the Project `<select>`: a "瀏覽目錄" toggle opens an inline panel with breadcrumb (`repos / sub`), "上一層" (hidden at root), the entry list (click an entry to enter it), "選擇此目錄" (disabled at root), and a name input with "建立並選擇" (create then select). `src/web/api.ts` currently drops server messages and shows generic text for unknown codes, so add short Chinese messages for `invalid_directory_path`, `directory_exists`, `directory_create_failed`, `project_discovery_collision` to the existing error mapping, and the panel displays them. On a successful select it calls `onSelected(project)`.
- `src/web/main.tsx`: `onSelected` refreshes the Project list, then sets the active project the same way the existing `<select>` onChange does (`setProject`, `writeSessionView({version:1, projectId})`, `setNativeFile("")`) and closes the panel.

## Verification (each item maps to a requirement; anything else was dropped)
1. Unit `test/unit/project-picker.test.ts` (N1–N6): path validation rejects `..`, absolute, hidden, backslash, symlink segments and root-escape; list shows only real non-hidden directories; create works, rejects bad names and existing names, and makes no `.git`; root selection (`""`) is rejected; names/paths at the 255-byte session-dir-name boundary (multi-byte UTF-8 case) are accepted at the limit and rejected above it with no directory created; select persists, and a restart is simulated by calling `loadConfig()` again from the original static config and the same data dir (not by cloning a populated config and not via `GET /projects`): the picked project has the same id, `sessionDir === piSessionDirectory(...)`, and an existing session file in that sessionDir is listed; a deleted picked directory is skipped without error; selecting a first-level directory returns the existing id; selecting a directory equal to or colliding with a static project preserves/rejects before persisting; a corrupt persistence file is treated as empty. Why keep: these are the whole security boundary and persistence contract. The existing `project-discovery.test.ts` must still pass (N6).
2. API test in the same file `test/unit/project-picker.test.ts` via `createApp` (N1–N3): the three routes work end to end; unauthenticated request → 401 (new routes touch the file system); assert error codes and statuses: `directory_exists` → 409, invalid path → 400, a missing path → 400 `invalid_directory_path` (not 500). Why keep: verifies the contract that the web layer uses. No further per-error matrix.
3. One Playwright e2e `test/e2e/nested-picker.spec.ts` (N1–N3): (a) browse into a nested non-git container directory and use "選擇此目錄", verify its existing session appears; (b) create a folder, it becomes the selected Project, "新建 Session" creates a session whose project is that directory: the POST `/api/v1/sessions` response has the picked project id, the native file sits under the expected `sessionDir`, and the native header `cwd` equals the directory. Page reload showing the Project is only UI evidence; restart persistence is proven by item 1. Why keep: only a real browser against the e2e fixture server (`test/fixtures/web-server.mjs`, which imports TypeScript sources and builds its config manually) verifies the UI drives the required flow, including the direct-select button. No mobile/styling/performance tests: they do not affect requirement correctness.
4. Final gate by main agent: `npm run check` (already includes format, lint, typecheck, unit tests, build) and the e2e specs `project-discovery` and `nested-picker`; no separate repeat of the task gates. No production service restart (not authorized for this change).
