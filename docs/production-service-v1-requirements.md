# 正式服務安全部署與登入 v1：需求確認

**狀態：需求與驗收語義供可攜部署參考；歷史部署及有限驗證摘要見[驗證文件](production-service-v1-verification.md)。本文不表示此 clone 有執行中的服務。**

## 背景與使用情境

Owner 需要安全部署服務、管理登入 token，並以瀏覽器存取同一主機上的介面。部署者須自行提供主機、設定、私有資料目錄與憑證管理。Owner token 是登入憑證，不是模型 API key。

## 範圍與限制

需求涵蓋可信候選產物、固定且不可變的 release、原子更新啟動指標、沿用由 Owner 管理的設定與 token、正常啟停、部署後有限驗證，以及可判讀的命令結果與限制。具體部署方式應遵守階段 review gate；本文件不代表已建置或部署。

不更換既有 token，不修改個人 JSONL、Pi 設定、VPN、防火牆或正式資料。不送出模型 prompt，不啟動真模型測試，不擅自執行 git commit。HTTP over Tailnet 不等於 HTTPS；正式長期營運建議使用 HTTPS。部署者自行負責資料備份、service manager 與災難復原。

## 功能需求

### R01：核對候選產物

部署前核對候選產物的來源、完整性與安全修補內容。舊報告不足時，須在另行核准的隔離範圍重新建置與測試。不得直接信任不明的既有 build 產物。

### R02：保留舊 release

新 release 不得覆寫或刪除舊 release。保留舊版不表示可安全自動回復；舊版若有已知安全缺口，不得自動啟動。

### R03：記錄切換前基準

切換前記錄必要的 pointer、設定、憑證檔 metadata/hash、受保護資料與程序基準。不得輸出或保存 token 值。資料核對須限定明確範圍，避免掃描無關個人資料。

### R04：核對啟動條件

啟動前核對 listener、服務身分與受管 writer。狀態不明或程序清理失敗時，阻擋部署。不得刪除 lock 或強制終止程序。

### R05：沿用 Owner 管理的憑證

使用 Owner 私下管理的設定與 token。不得將 token 放入 URL、日誌、報告或對話。軟體不會自動建立或管理 token。

### R06：有限驗證

依事先核准的範圍驗證 health、靜態資產、登入、未登入 API 防護與 encoded-route regression。會建立 cookie 的登入驗證，須另定測試會話及清理方式。不得在正式資料上執行 mutation regression。

### R07：交付操作方式

文件應提供可攜的建置、設定、啟動、正常停止及登入說明，並清楚列出所需的主機管理設定。不得假設 repository 提供私有主機腳本。

### R08：區分證據範圍

分開列出歷史結果、本輪結果與未驗證範圍。不得以退出碼 0 代替驗收，也不得把有限檢查描述為全面安全保證。

## 錯誤處理

- 產物不可驗證、介面位址不符、port 佔用或程序狀態不明時停止。
- 啟動或安全驗證失敗時，以正常停止為原則。
- 停止失敗時，回報存活程序與風險。不得宣稱服務已關閉。
- 不自動啟動已知有安全缺口的舊版。
- 不自動重送結果未知的操作。

## 驗收語義

A01 候選產物來源與完整性可追溯。A02 listener 與核准範圍內的有限驗證有證據。A03 受保護檔案差異依事前白名單核對，並如實保留事故。A04 token 只在限定範圍內檢查，不宣稱全主機掃描。A05 操作說明須可攜，並標示未實測的步驟。A06 需由負責人 review；文件更新不等於 review 完成。

## 公開發布限制

公開 commit 只包含文件。不得提交 token、資料庫、原生 history、logs、私有設定或 release 產物。既有部署及其私有資料不受文件更新影響。公開發布前須掃描候選工作樹與可達 Git 歷史；掃描結果不等於全面安全保證。

## 取捨

優先採用最小變更，保留舊 release 供診斷，但不自動 rollback。長期 service manager、正式資料目錄與 HTTPS 應由獨立部署決策處理。現階段不承諾零停機。
